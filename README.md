# Hylme แอดมินรายวัน

เว็บสรุปแชทรายวันจากแท็ก Pancake ของ 4 เพจ Hylme ดูได้ที่ https://chinathiphylme-ctrl.github.io/hylme-admin/

## อัปโหลดไฟล์ทุกวัน

1. ใน Pancake export **สถิติแท็กแบบแยกเพจ** ของเมื่อวาน (ไม่ใช่แบบรวมทุกหน้า)
2. export **ไฟล์ข้อความ** ของเมื่อวาน ทุกเพจ
3. export **ออเดอร์** ของเมื่อวาน (ไฟล์ `orders_วันเดือน.xlsx`) ใช้ดูยอดขายรายแอดมิน
4. เปิดเว็บ → เมนู **อัปโหลดไฟล์** → ลากไฟล์ทั้งหมดมาวาง
5. ดูสรุปไฟล์ที่อ่านได้ ถ้ามีข้อความ "จะทับข้อมูลเดิม" แปลว่าวันนั้นเคยอัปโหลดแล้ว
6. ใส่รหัสอัปโหลด แล้วกด **บันทึก**

ไฟล์ข้อความและไฟล์ออเดอร์ถูกอ่านในเบราว์เซอร์ ชื่อลูกค้า เบอร์โทร ที่อยู่ และเนื้อหาข้อความจะถูกตัดทิ้งก่อนส่งขึ้นฐานข้อมูล ชื่อพนักงานใน Pancake แปลงเป็นชื่อเล่นตาม `src/config/admins.ts`

ถ้าเจอแท็กใหม่ที่ยังไม่จัดกลุ่ม ไปที่เมนู **จัดกลุ่มแท็ก** แล้วเลือกกลุ่ม (ต้องใช้รหัสเดียวกัน)

## ตั้งหรือเปลี่ยนรหัสอัปโหลด

ต้องตั้งรหัสครั้งแรกก่อนจะอัปโหลดได้ (ถ้ายังไม่ตั้ง เว็บจะขึ้นว่ารหัสไม่ถูกต้องทุกครั้ง) เข้า Supabase → โปรเจกต์ `hylme-admin` → SQL Editor แล้วรัน (เปลี่ยน `รหัสใหม่`):

```sql
insert into settings (key, value)
values ('upload_code', extensions.crypt('รหัสใหม่', extensions.gen_salt('bf', 10)))
on conflict (key) do update set value = excluded.value;
```

ใช้รหัสยาวอย่างน้อย 10 ตัว ผสมตัวอักษรและตัวเลข ฐานข้อมูลเก็บเฉพาะ hash ของรหัส ไม่มีใครอ่านรหัสจริงได้ และใส่รหัสผิดแต่ละครั้งต้องรอ 1 วินาที

## ถ้าเว็บขึ้นว่าโหลดข้อมูลไม่ได้

Supabase แบบฟรีจะหยุดพักเองถ้าไม่มีใครใช้ 7 วัน ให้เจ้าของเข้า Supabase แล้วกด **Restore project**

## สำหรับนักพัฒนา

```bash
npm install
npm test          # ทดสอบ parse / grouping / metrics
npm run dev       # เปิดเว็บในเครื่อง (ใช้ .env.local)
npm run verify    # เทียบตัวเลขกับไฟล์ export จริงในโฟลเดอร์แม่ (ไม่ขึ้น git)
```

push เข้า `main` แล้ว GitHub Actions จะ build และขึ้น GitHub Pages ให้เอง โครงสร้างฐานข้อมูลอยู่ที่ `supabase/migrations/`

## หัวข้อ เหตุผล และอัตราปิดรายแอดมิน (11 พ.ย. 2026)

- หน้า **เสียงลูกค้า** มีเหตุผลที่ซื้อ/ยังไม่ซื้อจากแท็กแอดมิน และขั้นสุดท้ายของแชทใหม่ที่ยังไม่ปิด ใช้ตัวกรองช่วงเวลาและเพจด้านบน
- เมื่ออัปโหลดไฟล์ข้อความ ระบบอ่านหัวข้อจากคำค้น เก็บเฉพาะชื่อหัวข้อต่อแชท และแสดงประโยคให้เลือกเก็บไม่เกิน 30 ประโยคต่อไฟล์ ประโยคที่ไม่เลือกอยู่เฉพาะหน้านี้ ไม่มีการบันทึกอัตโนมัติ
- ก่อนกดเก็บประโยค ต้องตรวจชื่อหรือข้อมูลระบุตัวลูกค้าเพิ่มเติม ระบบกรองที่อยู่/อีเมลและปิดเบอร์โทรให้แล้ว แต่คำค้นไม่รับประกันว่าจะตรวจข้อมูลส่วนบุคคลได้ทุกแบบ
- อัตราปิดรายแอดมินนับแชทที่เริ่มตั้งแต่ **4 พ.ย. 2026** ในช่วงที่เลือกและมีแท็ก `พี่ก้อย` หรือ `นุ่น🤍` แชทที่มีสองชื่อจะนับให้ทั้งสองคน ยอดขายยังนับจากไฟล์ออเดอร์
- รายงานยอดขายแอดมินไม่นับบัญชี `chinathiphylme` ตามที่ทีมกำหนด ยอดรวม จำนวนออเดอร์ สัดส่วน สินค้า และแหล่งที่มาในรายงานนี้คำนวณหลังตัดบัญชีนี้ออก โดยไม่ลบออเดอร์ต้นทาง
- การ์ดเกรดลีดอธิบายทั้งเกณฑ์ A/B/C/D และเหตุผลที่พบจริงพร้อมจำนวนแชทในช่วงที่เลือก ใช้กฎชุดเดียวกับการจัดเกรด; แชทหนึ่งอาจเข้าได้หลายเหตุผลในเกรดเดียวกัน
- อันดับโฆษณาเรียงตามขอบล่าง Wilson 90% เฉพาะโฆษณาที่มีอย่างน้อย 15 แชท กลุ่มข้อมูลน้อยอยู่ในรายการพับ

**ก่อนเปิดใช้การเก็บหัวข้อ:** ตรวจฟังก์ชัน `save_messages` ปัจจุบันกับไฟล์ `supabase/migrations/0004_topics.sql` แล้วรัน migration แบบ transaction บน Supabase ระบบเก่ายังเปิดอ่านได้ แต่การอัปโหลดข้อความเวอร์ชันนี้จะหยุดพร้อมแจ้งเหตุผลถ้ายังไม่มีคอลัมน์ `topics` เพื่อไม่ให้หัวข้อหายโดยไม่มีคำเตือน หลัง migration ให้อัปไฟล์ข้อความเก่าซ้ำเพื่อคำนวณหัวข้อ (ข้อมูลวัน/เพจเดิมจะถูกแทนที่ตามขั้นตอนปกติ) อย่าอัปทับข้อมูลจริงเพื่อทดสอบระบบ

ตรวจไฟล์จริงโดยไม่แสดงข้อความลูกค้า: `npx tsx scripts/check-topics.ts`
