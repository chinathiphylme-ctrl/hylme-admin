# Hylme แอดมินรายวัน

เว็บสรุปแชทรายวันจากแท็ก Pancake ของ 4 เพจ Hylme ดูได้ที่ https://chinathiphylme-ctrl.github.io/hylme-admin/

## อัปโหลดไฟล์ทุกวัน

1. ใน Pancake export **สถิติแท็กแบบแยกเพจ** ของเมื่อวาน (ไม่ใช่แบบรวมทุกหน้า)
2. export **ไฟล์ข้อความ** ของเมื่อวาน ทุกเพจ
3. export **ออเดอร์** ของเมื่อวาน (ไฟล์ `orders_วันเดือน.xlsx`) ใช้ดูยอดขายรายแอดมิน
4. เปิดเว็บ → เมนู **อัปโหลดไฟล์** → ลากไฟล์ทั้งหมดมาวาง
5. ดูสรุปไฟล์ที่อ่านได้ ถ้ามีข้อความ "จะทับข้อมูลเดิม" แปลว่าวันนั้นเคยอัปโหลดแล้ว
6. ใส่รหัสอัปโหลด แล้วกด **บันทึก**

ไฟล์ข้อความและไฟล์ออเดอร์ถูกอ่านในเบราว์เซอร์ ชื่อลูกค้า เบอร์โทร ที่อยู่ และเนื้อหาข้อความจะถูกตัดทิ้งก่อนส่งขึ้นฐานข้อมูล ชื่อพนักงานใน Pancake แปลงเป็นชื่อเล่นตาม `src/config/admins.ts`

ถ้าเจอแท็กใหม่ที่ยังไม่จัดกลุ่ม ไปที่เมนู **จัดกลุ่มแท็ก** แล้วเลือกกลุ่ม (ต้องใช้รหัสเดียวกัน)

## ตั้งหรือเปลี่ยนรหัสอัปโหลด

ต้องตั้งรหัสครั้งแรกก่อนจะอัปโหลดได้ (ถ้ายังไม่ตั้ง เว็บจะขึ้นว่ารหัสไม่ถูกต้องทุกครั้ง) เข้า Supabase → โปรเจกต์ `hylme-admin` → SQL Editor แล้วรัน (เปลี่ยน `รหัสใหม่`):

```sql
insert into settings (key, value)
values ('upload_code', extensions.crypt('รหัสใหม่', extensions.gen_salt('bf', 10)))
on conflict (key) do update set value = excluded.value;
```

ใช้รหัสยาวอย่างน้อย 10 ตัว ผสมตัวอักษรและตัวเลข ฐานข้อมูลเก็บเฉพาะ hash ของรหัส ไม่มีใครอ่านรหัสจริงได้ และใส่รหัสผิดแต่ละครั้งต้องรอ 1 วินาที

## ถ้าเว็บขึ้นว่าโหลดข้อมูลไม่ได้

Supabase แบบฟรีจะหยุดพักเองถ้าไม่มีใครใช้ 7 วัน ให้เจ้าของเข้า Supabase แล้วกด **Restore project**

## หัวข้อ เหตุผล และอัตราปิดรายแอดมิน (11 พ.ย. 2026)

- หน้า **เสียงลูกค้า** มีเหตุผลที่ซื้อ/ยังไม่ซื้อจากแท็กแอดมิน และขั้นสุดท้ายของแชทใหม่ที่ยังไม่ปิด ใช้ตัวกรองช่วงเวลาและเพจด้านบน
- เมื่ออัปโหลดไฟล์ข้อความ ระบบอ่านหัวข้อจากคำค้น เก็บเฉพาะชื่อหัวข้อต่อแชท และแสดงประโยคให้เลือกเก็บไม่เกิน 30 ประโยคต่อไฟล์ ประโยคที่ไม่เลือกอยู่เฉพาะหน้านี้ ไม่มีการบันทึกอัตโนมัติ
- ก่อนกดเก็บประโยค ต้องตรวจชื่อหรือข้อมูลระบุตัวลูกค้าเพิ่มเติม ระบบกรองที่อยู่/อีเมลและปิดเบอร์โทรให้แล้ว แต่คำค้นไม่รับประกันว่าจะตรวจข้อมูลส่วนบุคคลได้ทุกแบบ
- อัตราปิดรายแอดมินนับแชทที่เริ่มตั้งแต่ **4 พ.ย. 2026** ในช่วงที่เลือกและมีแท็ก `พี่ก้อย` หรือ `นุ่น🤍` แชทที่มีสองชื่อจะนับให้ทั้งสองคน ยอดขายยังนับจากไฟล์ออเดอร์
- รายงานยอดขายแอดมินไม่นับบัญชี `chinathiphylme` ตามที่ทีมกำหนด ยอดรวม จำนวนออเดอร์ สัดส่วน สินค้า และแหล่งที่มาในรายงานนี้คำนวณหลังตัดบัญชีนี้ออก โดยไม่ลบออเดอร์ต้นทาง
- การ์ดเกรดลีดอธิบายทั้งเกณฑ์ A/B/C/D และเหตุผลที่พบจริงพร้อมจำนวนแชทในช่วงที่เลือก ใช้กฎชุดเดียวกับการจัดเกรด; แชทหนึ่งอาจเข้าได้หลายเหตุผลในเกรดเดียวกัน
- อันดับโฆษณาเรียงตามขอบล่าง Wilson 90% เฉพาะโฆษณาที่มีอย่างน้อย 15 แชท กลุ่มข้อมูลน้อยอยู่ในรายการพับ

**ก่อนเปิดใช้การเก็บหัวข้อ:** ตรวจฟังก์ชัน `save_messages` ปัจจุบันกับไฟล์ `supabase/migrations/0004_topics.sql` แล้วรัน migration แบบ transaction บน Supabase ระบบเก่ายังเปิดอ่านได้ แต่การอัปโหลดข้อความเวอร์ชันนี้จะหยุดพร้อมแจ้งเหตุผลถ้ายังไม่มีคอลัมน์ `topics` เพื่อไม่ให้หัวข้อหายโดยไม่มีคำเตือน หลัง migration ให้อัปไฟล์ข้อความเก่าซ้ำเพื่อคำนวณหัวข้อ (ข้อมูลวัน/เพจเดิมจะถูกแทนที่ตามขั้นตอนปกติ) อย่าอัปทับข้อมูลจริงเพื่อทดสอบระบบ

ตรวจไฟล์จริงโดยไม่แสดงข้อความลูกค้า: `npx tsx scripts/check-topics.ts`

## ระบบติดตามลูกค้า 7 รอบ (เมนู "ติดตาม 7 รอบ" และ "รายงาน GM")

ติดตามลูกค้าที่ทักแล้วยังไม่ซื้อ 7 รอบ ระยะห่างตามบรีฟ (วันที่ 2 / 5 / 7 / 14 / 30 / 45 / 60 ถ้าตามตรงวันทุกรอบ) ตั้งแต่ 23 พ.ย. 2026 รอบถัดไปนับจากวันที่บันทึกรอบก่อนหน้าจริง ทีมใส่รหัสทีมครั้งเดียวต่อเครื่อง แล้วเลือกชื่อตัวเอง (เครื่องจำไว้ ครั้งต่อไปเข้าได้เลย) ทุกคนเห็นลูกค้าทั้งหมดและบันทึกแทนกันได้ ประวัติขึ้นชื่อคนที่เลือก คนที่ไม่มีรหัสเห็นข้อมูลลูกค้าไม่ได้ แท็บอื่นยังเปิดดูได้โดยไม่ต้องเข้าสู่ระบบเหมือนเดิม

### ติดตั้งครั้งแรก (เจ้าของระบบ)

1. รัน `supabase/migrations/0005_followup.sql` ใน Supabase SQL Editor (สร้างชื่อ พี่ก้อย / นุ่น / GM ไว้ให้แล้ว)
2. Supabase → Authentication → Sign In / Providers → ปิด **Allow new users to sign up**
3. Authentication → Users → **Add user** สร้างบัญชีทีม 1 บัญชี อีเมล `followup@hylme.team` (ตั้งไว้ใน `src/config/team.ts` ไม่ต้องมีกล่องจดหมายจริง) + รหัสทีม ติ๊ก Auto Confirm
4. อนุญาตบัญชีนั้นใน SQL Editor:

```sql
insert into fu_team select id from auth.users where email = 'followup@hylme.team';
```

### ดูแลระบบ

- **เปลี่ยนรหัสผ่าน** (เช่น มีคนออก): Authentication → Users → บัญชีทีม → Reset password / ตั้งใหม่ แล้วบอกรหัสใหม่กับทีม เครื่องที่เข้าอยู่จะต้องเข้าสู่ระบบใหม่เมื่อหมดอายุ
- **เพิ่ม / เปลี่ยนชื่อ / ปิดชื่อคนในทีม**: ทำในเว็บ แท็บรายงาน GM → รายชื่อทีม ไม่ต้องใช้ SQL คนที่ปิดแล้วยังเป็นผู้ดูแลลูกค้าเดิม ย้ายได้ที่หน้าแก้ไขลูกค้า
- **คนอื่นจะใช้เครื่องนี้**: กด "เปลี่ยนคน" มุมขวาบนของแท็บติดตาม

### ใช้งานประจำวัน

- **ลูกค้าเข้าคิวเอง** — ติดแท็ก `ติดตาม` ในแชท Pancake ตามปกติ พออัปโหลดไฟล์ข้อความ แชทนั้นจะขึ้นในคิวติดตามเอง (หน้าอัปโหลดบอกว่าเพิ่มกี่ราย) ไม่ต้องพิมพ์ลูกค้าเข้าเว็บ ชื่อในคิวเป็น "เพจ · สินค้า · #เลขท้ายแชท" กดเปิดแชตได้ แก้ชื่อเองได้ที่ปุ่มแก้ไข
  - วันที่ 1 = วันแรกที่ระบบเห็นแท็ก `ติดตาม` ในไฟล์ที่อัปโหลด
  - ผู้ดูแล = คนแรกที่ติดแท็กชื่อตัวเอง (`พี่ก้อย` / `นุ่น🤍`) ถ้าไม่มีแท็กชื่อ ระบบให้คนที่มีลูกค้าค้างน้อยกว่า
  - แท็ก `ติดตาม2` … `ติดตาม7` = ตามไปแล้วถึงรอบนั้น ระบบบันทึกรอบให้ (ประวัติขึ้น "ระบบ")
  - แชทในคิวที่ได้แท็ก `ปิด` / `ปิดAds` / `ปิดOrganic` หลังเข้าคิว → ซื้อแล้วอัตโนมัติ ยอดเงินยังต้องใส่เลขออเดอร์
  - แชทที่ซื้อไปแล้วก่อนติดแท็กติดตามจะไม่ถูกดึงเข้า แชทที่เข้าคิวช้าเริ่มรอบ 1 ในวันที่เข้าคิว (ไม่ข้ามรอบให้แล้ว ตั้งแต่ 23 พ.ย. 2026)
- **แชทเงียบใหม่ ยังไม่ได้ตาม** (กล่องบนสุดของ "งานติดตามวันนี้" แทนเมนู "ต้องตามวันนี้" เดิม ตั้งแต่ 20 พ.ย. 2026) — แชทที่ถึงขั้นขอราคา / ขอโปร / ลังเล / พร้อมสั่ง แล้วไม่เปิดอ่านหรืออ่านไม่ตอบ ในไฟล์ข้อความล่าสุดของแต่ละเพจ และยังไม่อยู่ในคิว ตามใน Pancake แล้วกด **บันทึกผล** → ลูกค้าเข้าคิว 7 รอบทันที ผลที่กดเป็นรอบ 1 รอบ 2 นับต่อจากวันนั้น ผู้ดูแล = คนที่กด ถ้า GM กด ระบบให้แอดมินตามแท็กชื่อ รายงาน GM มีบรรทัด "แชทเงียบใหม่: ขึ้นรายชื่อ / ตามแล้ว / ซื้อแล้ว"
- **งานติดตามวันนี้** — งานเลยกำหนดขึ้นก่อน แล้วตามด้วยงานวันนี้ กดชื่อลูกค้าเพื่อเปิดรายละเอียด
- **บันทึกผล** — เลือก ส่งข้อมูลแล้ว / รอลูกค้าตอบ / ซื้อแล้ว / ขอหยุดติดต่อ เขียนโน้ตแล้วกดบันทึก ซื้อแล้วให้ใส่เลขออเดอร์ Pancake (ใส่ทีหลังได้) ข้ามรอบต้องใส่เหตุผล
- รอบถัดไป = วันที่บันทึกรอบก่อนหน้า + ระยะห่าง (3 / 2 / 7 / 16 / 15 / 15 วัน) รอบ 1 = วันหลังคุยครั้งแรก หรือวันที่เข้าคิวถ้าเข้าช้า ตามช้ารอบถัดไปก็เลื่อนตาม ลูกค้าตอบก่อนกำหนดบันทึกล่วงหน้าได้ (เจ้าของระบบเปลี่ยนจากกฎบรีฟ "วันกำหนดไม่เลื่อน" เมื่อ 23 พ.ย. 2026)
- ช่อง "ซื้อแล้ว" บอก "จาก N คนในคิว" และหน้ารายชื่อลูกค้ามีบรรทัด "ตามตัวกรองนี้ N คน · ซื้อแล้ว W คน" (ตามช่องค้นหา + ผู้ดูแล ไม่ขึ้นกับช่องสถานะ)
- ซื้อแล้ว / ขอหยุดติดต่อ → หยุดงานรอบต่อไปทันที เปิดติดตามใหม่ได้แต่ต้องใส่เหตุผล
- ลิงก์แชตซ้ำบันทึกไม่ได้ ชื่อซ้ำมีคำเตือน
- ถ้าสองคนแก้ลูกค้าคนเดียวกันพร้อมกัน คนที่บันทึกทีหลังจะได้ข้อความให้โหลดใหม่ ไม่บันทึกทับ
- **งานวันนี้** แอดมินเริ่มที่ลูกค้าของตัวเอง GM เริ่มที่ทั้งทีม เปลี่ยนได้ที่ช่องผู้ดูแล
- **รายงาน GM** — ทุกคนเปิดดูได้ กรองตามช่วงเวลา แอดมิน เพจ สินค้า ยอดขายนับเฉพาะออเดอร์ที่ผูกไว้และพบในไฟล์ออเดอร์ Pancake ที่อัปโหลดแล้ว (ไม่นับยกเลิก/คืน) ออเดอร์ที่ยังไม่อัปโหลดขึ้นเป็น "รอตรวจ"
- นำเข้าข้อมูลจากเว็บแอป HTML ตัวเดิม: รายงาน GM → นำเข้าข้อมูล (CSV)

### ข้อจำกัด

- ไม่ส่งข้อความอัตโนมัติและไม่เชื่อม Facebook API — ระบบเตือนและบันทึก ส่วนการทักลูกค้าทำในแชตตามปกติ
- ยอดขายผูกด้วยเลขออเดอร์ที่แอดมินพิมพ์ ไฟล์ออเดอร์ Pancake ไม่มีชื่อลูกค้า จึงจับคู่ให้อัตโนมัติไม่ได้
- ชื่อในประวัติเป็นชื่อที่แต่ละคนเลือกเอง ระบบพิสูจน์ตัวตนรายคนไม่ได้ (ใช้รหัสร่วมกัน)
- ทุกคนที่มีรหัสลบลูกค้าได้ (ต้องกดยืนยันสองครั้ง) และประวัติของรายนั้นจะหายด้วย สำรองข้อมูลด้วยปุ่ม "ส่งออก CSV" และระบบสำรองของ Supabase
- ไฟล์ข้อความมีเฉพาะแชทที่ลูกค้าทักในวันนั้น ถ้าติดแท็ก `ติดตาม` หลังวันที่ลูกค้าทักครั้งสุดท้าย ระบบจะไม่เห็น ให้กด "+ เพิ่มลูกค้า" เอง (ใส่ลิงก์แชต ระบบจะผูกกับแชทให้)
- ลูกค้าที่ลบในเว็บแล้วจะไม่ถูกดึงกลับเข้ามาอีก แม้แชทยังมีแท็ก `ติดตาม`
- ก่อนใช้งานจริงควรตรวจ PDPA / นโยบายเก็บข้อมูล และข้อกำหนด Meta Messaging ตามบรีฟหน้า 14
