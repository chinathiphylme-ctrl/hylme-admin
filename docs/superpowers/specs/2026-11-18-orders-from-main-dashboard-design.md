# ประหยัดโควตา Supabase Free — Design (ฉบับสั้น)

วันที่ 18 พ.ย. 2026

## Intent

เจ้าของไม่อยากให้โปรเจกต์ Supabase `hylme-admin` ชนลิมิตแผนฟรีเร็ว (ฐานข้อมูล 500 MB, egress 5 GB/เดือน)
โปรเจกต์นี้ใช้ร่วมกันสองเว็บ: เว็บแอดมินรายวัน (repo นี้) และ dashboard หลัก (`Downloads\data sec`, schema `hylme_dash`)

## ทำไปแล้ว (18 พ.ย., เจ้าของอนุญาต)

- `VACUUM FULL hylme_dash.snapshots` → ฐานข้อมูล 193 MB → 50 MB (ตารางเหลือ 568 kB, 12 รอบครบ)
  สาเหตุ: รอบเก่าก่อน 17 พ.ย. เก็บทั้งก้อน ลบแล้วแต่พื้นที่ไม่คืน; รอบใหม่เป็น manifest เล็ก จึงไม่น่าบวมอีก

## Goals (เว็บแอดมิน — ลด egress)

- แชท (`conversations`) และสถิติแท็ก (`tag_daily`) เก็บไว้ในเบราว์เซอร์ทีละวัน เปิดครั้งต่อไปโหลดเฉพาะวันที่ใหม่/เปลี่ยน
  - รู้ว่าวันไหนเปลี่ยนจากฟังก์ชัน `day_sigs()` (migration 0007): ต่อวันคืนจำนวนแถว + md5 ของทุกแถว
  - ลำดับแถวต้องเหมือนเดิมทุกตัว (ฐานข้อมูลเรียงด้วย collation en_US ไม่ใช่แบบ JS) → เก็บแถวของแต่ละวันตามลำดับที่ฐานข้อมูลส่งมา แล้วต่อกันตามวัน
  - เบราว์เซอร์เก็บไม่ได้ (โหมดส่วนตัว ฯลฯ) หรือ `day_sigs` ยังไม่ติดตั้ง → โหลดแบบเดิม
- หน้าภาพรวม: แชทของช่วงที่เลือก + แชทวันล่าสุดของแต่ละเพจ ตัดจากแชททั้งหมดที่โหลดแล้ว ไม่ขอซ้ำ
- แท็บติดตาม หลังกดบันทึก: ดึง `id,version,updated_at` ของลูกค้าทั้งหมด → ดึงเต็มเฉพาะรายใหม่/เปลี่ยน, ตัดรายที่ถูกลบ;
  ประวัติเฉพาะ `id` ใหม่ (ย้อนเผื่อ 50 id กันลำดับ commit สลับ); ทีม + ออเดอร์ที่ผูก ดึงใหม่ (ตารางเล็ก);
  ออเดอร์ Pancake ดึงเฉพาะเลขที่ยังไม่มี. เปิดแท็บ / ล็อกอิน / เลือกชื่อ / ปุ่มโหลดใหม่ = โหลดเต็ม + sync แท็กเหมือนเดิม

## Non-goals / Anti-goals

- ตัวเลขและหน้าจอทุกแท็บต้องเหมือนเดิมทุกตัว (ตรวจด้วยข้อมูลจริง: แบบเดิม vs แบบใหม่ ต้องเท่ากันทุกแถว)
- ไม่แก้ dashboard หลัก (data sec) รอบนี้
- ไม่เก็บอะไรในเบราว์เซอร์ที่ไม่ได้เปิดให้ทุกคนอ่านอยู่แล้ว (แชท/แท็กเป็นข้อมูล public read อยู่แล้ว ไม่มีชื่อลูกค้า)

## Approaches

- **A. แคชรายวันในเบราว์เซอร์ + ตรวจด้วยลายเซ็นรายวัน ← เลือก** — ลดมากสุด ข้อมูลไม่ค้างเพราะเทียบ md5 ทุกครั้ง
- B. แคชตามเวลาอัปโหลด (ตาราง uploads) — ไม่ต้องมีฟังก์ชันใหม่ แต่พลาดถ้ามีอะไรแก้แถวโดยไม่บันทึกประวัติ
- C. ไม่แคช แค่ตัดคำขอซ้ำ — ง่ายสุด แต่ยังโหลดแชททั้งหมดทุกครั้งที่เปิด (ตัวใหญ่สุด)

## พักไว้ (เจ้าของบอกว่าเป้าหมายคือประหยัด)

- เชื่อมออเดอร์จาก dashboard หลัก (Pancake API ทุก 30 นาที) — ตรวจแล้วใช้ได้ (443/443 ออเดอร์ วัน/ยอด/จำนวนตรง)
  แต่ไม่ช่วยประหยัด; ถ้าทำ: `parseOrders` อ่านไฟล์แบบ API, เพจจาก `Facebook / <ชื่อเพจ>` เท่านั้น, `Telesales / x` → `Telesales`,
  ฟังก์ชัน `save_orders_auto` แทนแถวประวัติแถวเดียว, รหัสอัปโหลดใน `data sec/private/`
