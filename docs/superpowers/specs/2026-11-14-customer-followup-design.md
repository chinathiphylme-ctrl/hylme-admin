# ระบบติดตามลูกค้า 7 รอบ (ใน hylme-admin) — Design

วันที่ 14 พ.ย. 2026 · ที่มา: `HYLME_Customer_Followup_Dev_Brief.pdf` (15 หน้า) และเว็บแอปต้นแบบ `HYLME_Followup_WebApp.html`

## Intent

ทีม Sales Online (พี่ก้อย, นุ่น) ต้องไม่ลืมตามลูกค้าที่ทักแล้วยังไม่ซื้อ ตามกำหนด 7 รอบ (วันที่ 2/5/7/14/30/45/60 นับวันคุยครั้งแรกเป็นวันที่ 1)
GM ต้องเห็นงานค้างและผลของทีม แอดมิน 2 คนและ GM ใช้จากคนละเครื่องและเห็นข้อมูลชุดเดียวกัน

## Goals

- แท็บ **ติดตาม 7 รอบ** (งานวันนี้ / รายชื่อลูกค้า / แผน 7 รอบ) และแท็บ **รายงาน GM** ใน hylme-admin
- บัญชีทีมบัญชีเดียว (อีเมล + รหัสผ่าน, อยู่ใน `fu_team`) แล้วเลือกชื่อบนเครื่อง — ทุกคนเห็น/บันทึกลูกค้าทั้งหมด ประวัติขึ้นชื่อที่เลือก (เปลี่ยนจากล็อกอินรายคน 2026-11-14: เจ้าของต้องการให้ดูแลง่าย)
- บันทึกผลรอบ: ส่งข้อมูลแล้ว / รอลูกค้าตอบ / ซื้อแล้ว / ขอหยุดติดต่อ + โน้ต; เก็บเวลาจริงและผู้บันทึก; ประวัติลบไม่ได้
- ซื้อแล้ว → ใส่เลขออเดอร์ Pancake; ระบบตรวจว่าไม่ซ้ำ ดึงยอด/สินค้าจาก `pancake_orders`; ถ้ายังไม่อัปโหลด = "รอตรวจ"
- กันข้อมูลซ้ำ: ลิงก์แชตซ้ำ = บล็อก, ชื่อซ้ำ = เตือน
- ข้ามรอบต้องมีเหตุผล; บันทึกก่อนกำหนดได้; กำหนดรอบถัดไปไม่เลื่อน
- บันทึกพร้อมกัน: เลขเวอร์ชันต่อลูกค้า ถ้าเวอร์ชันไม่ตรง = แจ้งเตือน ไม่ทับ
- มือถือ: งานแสดงเป็นการ์ด บันทึกผลได้ใน 2–3 แตะ
- ส่งออก CSV (เฉพาะที่ตนมีสิทธิ์เห็น), นำเข้า CSV จากแอป HTML เดิม (GM)
- เวลาไทย (Asia/Bangkok) ทุกจุด

## Non-goals / Anti-goals

- ไม่ส่งข้อความอัตโนมัติ ไม่ต่อ Facebook/Meta API
- ไม่แตะการคำนวณหรือการเข้าถึงของแท็บเดิม (ยังเปิดอ่านได้ไม่ต้องล็อกอิน)
- รายงาน GM แสดงตัวเลขเป็นกลาง ไม่ใส่คำตัดสินดี/ไม่ดี
- ไม่เปิดเผยข้อมูลลูกค้าต่อผู้ไม่ได้ล็อกอิน (ตาราง follow-up ไม่มี policy สำหรับ anon)

## Approaches (เลือก B)

- A. HTML เดิม + Google Sheets/Apps Script — เร็ว ฟรี แต่ช้าต่อคลิก ผูกออเดอร์ Pancake ไม่ได้
- **B. แท็บใน hylme-admin + Supabase Auth/RLS** — สิทธิ์จริง ผูกออเดอร์จริง มีชุดทดสอบ/deploy อยู่แล้ว (งานมากสุด) ← ผู้ใช้เลือก
- C. HTML เดิม + Supabase — สิทธิ์จริงแต่มีสองเว็บต้องดูแล ทดสอบยาก

ผูกออเดอร์: เลือกแบบ ก (พิมพ์เลขออเดอร์ + ตรวจภายหลังได้) แทนแบบ ข (เลือกจากรายการ ต้องรออัปโหลด)

## Data (migration `0005_followup.sql`)

- `fu_team(user_id → auth.users)` บัญชีที่เข้าได้; `staff(id, name, role admin|gm, active)` รายชื่อคน จัดการจากเว็บ
- `fu_leads(id, name, product, owner_id, first_day, page_id, chat_url, objection, notes, status active|won|optout|paused, version, created/updated at/by)`; unique `chat_url` เมื่อไม่ว่าง
- `fu_events(id, lead_id, kind round|skip|status|reassign|edit|import, round_no, result, due_day, note, order_id, at, by)` — append-only
- `fu_orders(order_id PK, lead_id, linked_at, linked_by)` — 1 ออเดอร์ผูกได้ลูกค้าเดียว; ยอด/สถานะยกเลิกอ่านจาก `pancake_orders`
- อ่าน: RLS — เฉพาะบัญชีใน `fu_team` (anon และบัญชีอื่นไม่เห็นอะไร)
- เขียน: เฉพาะ RPC `security definer` ที่ตรวจสมาชิกทีม ชื่อผู้บันทึก (active) เวอร์ชัน และลำดับรอบ

## Rules

- รอบถัดไป = รอบเล็กสุดที่ยังไม่มี event `round` หรือ `skip`
- สถานะคำนวณ: won / optout / paused / ครบ 7 รอบ / เลยกำหนด / ถึงกำหนดวันนี้ / รอติดตาม
- แอดมินสร้างลูกค้าให้ตัวเองเท่านั้น; GM เลือกผู้ดูแลได้และย้ายผู้ดูแลได้; ลบลูกค้าได้เฉพาะ GM
- แก้วันคุยครั้งแรกไม่ได้หลังมีประวัติรอบแล้ว
- ยอดขายหลังติดตาม = ออเดอร์ที่ผูกไว้ ที่มีใน `pancake_orders` และสถานะไม่ใช่ยกเลิก/คืน

## Builder's calls

- ลูกค้าหนึ่งรายมีผู้ดูแลหลักคนเดียว; ใครในทีมก็บันทึกแทนได้ (ประวัติแสดงชื่อผู้บันทึก) ยอดนับให้ผู้ดูแล
- บัญชีทีมสร้างใน Supabase Dashboard แล้วเพิ่มใน `fu_team` ด้วย SQL หนึ่งบรรทัด; ชื่อคนเพิ่ม/ปิดจากเว็บ
- เปิดติดตามลูกค้าที่ซื้อแล้ว/ขอหยุดอีกครั้งต้องใส่เหตุผล (แทนกฎ GM เท่านั้น)
