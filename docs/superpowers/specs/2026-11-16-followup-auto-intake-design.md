# ดึงลูกค้าเข้าคิวติดตามอัตโนมัติจากแท็ก "ติดตาม" — Design

วันที่ 16 พ.ย. 2026 · ต่อจาก `2026-11-14-customer-followup-design.md`

## Intent

เจ้าของไม่อยากให้ GM หรือแอดมินต้องพิมพ์ลูกค้าเข้าระบบทีละราย และไม่อยากให้ GM ต้องแจกงาน
ลูกค้าควรไหลเข้าคิวของแอดมินเอง ส่วน GM ดูอย่างเดียวว่าใครทำอะไรไปแล้ว

ทีมติดแท็ก `ติดตาม` ใน Pancake อยู่แล้ว (176 แชทตั้งแต่ 31 ต.ค., ~14 แชทใหม่/วันใน 7 วันล่าสุด)
และใช้ `ติดตาม2` / `ติดตาม3` / `ติดตาม4` หมายถึง "ตามไปแล้วรอบที่ 2 / 3 / 4" (เจ้าของยืนยัน 16 พ.ย.)

## Goals

- แชทที่มีแท็ก `ติดตาม` หรือ `ติดตามN` เข้าคิวติดตามเองหลังอัปโหลดไฟล์ข้อความ ไม่ต้องกดอะไรเพิ่ม
- ผู้ดูแล = แท็กชื่อแอดมิน (`พี่ก้อย` / `นุ่น🤍`) ที่ปรากฏก่อน; ไม่มีแท็กชื่อ → แอดมินที่มีงานเปิดน้อยกว่า (เท่ากัน → เรียงตามชื่อ)
- วันที่ 1 = วันแรกที่ระบบเห็นแท็ก `ติดตาม` (หรือ `ติดตามN` ตัวแรก) บนแชทนั้น
- `ติดตามN` → รอบ 1..N ที่ยังไม่มีบันทึก ถูกบันทึกเป็น "ทำแล้ว (จากแท็ก Pancake)" ผู้บันทึก = ระบบ
- แชทในคิวที่ได้แท็กปิด (`ปิด` / `ปิดAds` / `ปิดOrganic`) ที่**เห็นครั้งแรกหลังเข้าคิว** → ซื้อแล้วอัตโนมัติ (ไม่มีเลขออเดอร์ ใส่ทีหลังได้)
- ตอนดึงเข้า รอบที่กำหนดก่อนวันนี้และยังไม่มีบันทึก → ข้ามอัตโนมัติ เหตุผล "เข้าระบบทีหลัง" (ใช้กับ 176 แชทเดิมและแชทที่อัปโหลดช้า) — คิวไม่ขึ้นงานค้างแดงร้อยรายการในวันแรก
- ชื่อในคิว: ไม่มีชื่อลูกค้าในฐานข้อมูล → ตั้งชื่อเป็น `<เพจ> · <สินค้าแท็กแรก หรือ "ไม่ระบุ"> · #<4 ตัวท้ายของรหัสแชท>`; แก้ชื่อเองได้ในฟอร์มแก้ไข
- ลิงก์แชต = `pancake_url` ของแชท ใช้ปุ่ม "เปิดแชต" เดิม
- ปุ่ม "+ เพิ่มลูกค้า" แบบพิมพ์เองยังอยู่ สำหรับแชทที่ระบบมองไม่เห็น
- ประวัติลูกค้าแสดงว่า "เข้าคิวอัตโนมัติจากแท็กติดตาม" และเหตุการณ์อัตโนมัติขึ้นผู้บันทึกเป็น "ระบบ"

## Non-goals / Anti-goals

- ไม่เขียนแท็กกลับไป Pancake (ไม่มี API) — บันทึกในเว็บกับแท็กใน Pancake อยู่คู่กันได้
- ไม่ดึงแชทที่ไม่มีแท็กติดตาม (คำนวณแล้ว ~500 งาน/วัน ทำไม่ไหว)
- ไม่ลบหรือหยุดลูกค้าเองเมื่อแท็ก `ติดตาม` ถูกถอดใน Pancake — หยุดได้ด้วยมือในเว็บ
- ไม่ตั้ง "หยุดติดต่อ" อัตโนมัติจากแท็กอื่น (ไม่สนใจ ฯลฯ) — แอดมินตัดสินเอง
- ไม่เปลี่ยนตัวเลขหรือการเข้าถึงของแท็บอื่น; การอัปโหลดต้องไม่ล้มเพราะขั้นดึงเข้าคิวล้ม
- ไม่เก็บชื่อ/เบอร์ลูกค้าเพิ่มจากไฟล์ (กฎความเป็นส่วนตัวของเว็บเดิม)

## Constraints

- ไฟล์ข้อความมีเฉพาะแชทที่ลูกค้าทักวันนั้น และแท็กเป็นแท็กปัจจุบันตอน export → ถ้าติดแท็กหลังวันที่ลูกค้าทักครั้งสุดท้าย ระบบไม่เห็น (บอกในคู่มือ)
- แท็กปิดในไฟล์อาจค้างจากการซื้อครั้งก่อน → นับเฉพาะแท็กปิดที่ `conv_tag_seen` เห็นครั้งแรกหลังวันเข้าคิว (แท็กที่เป็น baseline ไม่นับ)
- `conv_tag_seen.first_day` เป็น null เมื่อ baseline → วันที่ 1 ใช้วันแรกของแถว `conversations` ที่มีแท็กนั้นแทน
- อัปโหลดใช้ "รหัสอัปโหลด" ไม่ใช่บัญชีทีม → ขั้นดึงเข้าคิวต้องทำงานฝั่งฐานข้อมูลโดยไม่ต้องล็อกอินทีม
- ทำซ้ำได้ไม่เกิดซ้ำ: อัปไฟล์เดิมซ้ำ หรือรันซ้ำ ต้องไม่สร้างลูกค้า/รอบซ้ำ (ผูกด้วยรหัสแชท)
- เวลาไทยทุกจุด; Supabase โปรเจกต์นี้มีตารางของแอปอื่น (`web_orders`) ห้ามแตะสิทธิ์ของมัน

## Approaches

- A. แอดมินกดเพิ่มเอง (ของเดิม) — ไม่ต้องแก้ แต่เหนื่อยและลืมได้
- **B. ระบบสร้างงานจากไฟล์ที่อัปโหลด ← เลือก**
  - B1. ทุกแชทที่ยังไม่ปิด — ~500 งาน/วัน ทำไม่ไหว
  - B2. เฉพาะเกรด A — ~380 งาน/วัน ยังเยอะเกิน
  - **B3. เฉพาะแชทที่ทีมติดแท็ก "ติดตาม" ← เลือก** (ทีมใช้อยู่แล้ว ปริมาณ ~100 งาน/วันเมื่อรอบเต็ม)
  - B4. เกรด A จำกัดจำนวนต่อวัน — ระบบตัดลูกค้าด้วยตัวเลขที่ตั้งเอง

## Data

- `fu_leads.conversation_id text` (unique เมื่อไม่ว่าง) และ `fu_leads.source text` (`manual` | `tag`)
- `fu_events.kind` เพิ่ม `auto` สำหรับ "เข้าคิวอัตโนมัติ"; เหตุการณ์อัตโนมัติมี `by = null` แสดงเป็น "ระบบ"
- ฟังก์ชัน `fu_sync()` (security definer, idempotent) อ่าน `conversations` + `conv_tag_seen` แล้วสร้าง/อัปเดตตามกฎด้านบน คืนจำนวนที่เพิ่ม/อัปเดต

## Builder's calls

- เรียก `fu_sync()` ท้าย `save_messages` ใน savepoint (ถ้าล้ม → อัปโหลดยังสำเร็จ และแจ้งเตือนในหน้าอัปโหลด) และเรียกอีกครั้งตอนเปิดแท็บติดตาม เพื่อกันกรณีพลาด
- หน้าอัปโหลดบอกผล "เพิ่มเข้าคิวติดตาม X ราย · ซื้อแล้ว Y ราย"
- ลูกค้าที่เพิ่มเองด้วยลิงก์แชตเดียวกับแชทที่มีแท็ก → ผูกรหัสแชทให้ ไม่สร้างซ้ำ
- งานต่อวันประเมินจากข้อมูล 9–15 พ.ย.; ถ้าเยอะเกินจริง ค่อยพิจารณา B4 ภายหลัง
- ข้ามอัตโนมัติ "เข้าระบบทีหลัง" ทำ**ครั้งเดียวตอนดึงเข้า** เท่านั้น หลังจากนั้นรอบที่เลยกำหนดขึ้นเป็นงานค้างตามปกติ
- `ติดตามN` ที่เห็นทีหลังก็นำมาบันทึกรอบ 1..N ที่ยังว่างได้ทุกครั้งที่ sync; N เกิน 7 ถือเป็น 7
- แชทที่มีแท็กปิดเห็นครั้งแรก (หรือ baseline) ในวันเดียวกับหรือก่อนแท็กติดตาม → ไม่ดึงเข้า (ซื้อไปแล้ว ไม่มีอะไรต้องตาม) — ปัจจุบัน 16 จาก 176 แชท; ถ้าต้องการตามจริงให้เพิ่มเอง
- ผู้ดูแลกำหนดครั้งเดียวตอนดึงเข้า แท็กชื่อที่เปลี่ยนทีหลังไม่ย้ายผู้ดูแล (ย้ายเองได้ในฟอร์ม); ปัจจุบัน 63 จาก 176 แชทไม่มีแท็กชื่อ → ระบบแบ่งให้, 12 แชทมีทั้งสองชื่อ → คนที่เห็นแท็กก่อน (วันเดียวกัน → แบ่งตามงานน้อยกว่า)
- ลูกค้าที่ถูกลบในเว็บ ระบบจำรหัสแชทไว้และไม่ดึงกลับเข้ามาอีก
- ลูกค้าที่ซื้อแล้ว/หยุดติดต่อ แล้วแชทเดิมได้แท็กติดตามอีก → ไม่เปิดใหม่เอง (เปิดเองได้ในเว็บพร้อมเหตุผลตามกฎเดิม)
- รายงาน GM: รอบจากแท็ก `ติดตามN` นับเป็น "ติดตามแล้ว" ของผู้ดูแล; รอบที่ข้ามอัตโนมัติไม่นับ; ซื้อแล้วอัตโนมัติขึ้นในตัวเลข "ซื้อแล้ว" แต่ยอดเงินนับเมื่อผูกเลขออเดอร์เท่านั้น
- ทดสอบด้วยชุดทดสอบฐานข้อมูลเดิม (`tests/followup-db.test.ts`) เพิ่มกรณี: ดึงซ้ำไม่ซ้ำ, ติดตามN, ปิดค้าง, ไม่มีแท็กชื่อ, ลบแล้วไม่กลับ, sync ล้มแต่อัปโหลดผ่าน
