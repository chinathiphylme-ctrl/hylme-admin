# จับคู่ออเดอร์กับแชท ด้วยเลขแชทจาก Pancake API — Design

วันที่ 28 พ.ย. 2026

## Intent

เจ้าของอยากรู้ว่าออเดอร์ไหนแอดมินยังไม่ได้ติดแท็กปิดในแชท ("ปิดใน POS 30 คน แต่ติดแท็กปิดแค่ 28")
เพื่อให้ข้อมูลสาเหตุการซื้อ/ไม่ซื้อครบ (ต่อจาก `2026-11-27-tag-completeness-check-design.md`)
เทียบรายวันไม่ได้ เพราะวันที่ในออเดอร์คือวันที่แอดมินกดยืนยัน ซึ่งบางทีช้ากว่าวันที่ลูกค้าตกลงซื้อ
และแท็กปิดเก่าค้างจากการซื้อครั้งก่อน จึงต้องจับคู่ออเดอร์กับแชทเป็นรายใบ

## ข้อเท็จจริงที่ตรวจแล้ว

- ไฟล์ออเดอร์ Excel ไม่มีเลขแชท (ช่อง Chat page = ชื่อเพจ)
- ออเดอร์จาก Pancake POS API มี `conversation_id` ในรูปแบบเดียวกับไฟล์ข้อความ (`<page_id>_<psid>`, LINE = `ln_…`)
- 20–26 พ.ย.: ออเดอร์ที่มีเลขแชท 182 ใบ · เจอแชทใน `conversations` 171 (อีก 11 เป็น LINE) · ติดแท็กปิดแล้ว 139 · ยังไม่ติด 32
- เบอร์โทรใช้ไม่ได้ดี: ไฟล์ข้อความมีเบอร์แค่ 8–21 แชทต่อวัน ขณะที่ออเดอร์จากเพจ 20–30 ใบต่อวัน

## Goals

1. **ส่งคู่ "เลขออเดอร์ ↔ เลขแชท" เข้าเว็บแอดมินทุกชั่วโมง** จากตัวดึงออเดอร์ที่รันอยู่แล้วบนเครื่องนี้
   - `HYLME_CRM_V3/tools/pancake_export.py`: รับ `--chats FILE` แล้วเขียน JSON
     `[{ order_id, conversation_id, page_id, day }]` ของทุกออเดอร์ที่เขียนลง xlsx และมี `conversation_id`
     (`order_id` = ค่าเดียวกับช่อง `รหัสคำสั่งซื้อ`, `page_id` = `o.page_id` หรือ `o.page.id`,
     `day` = วันยืนยัน (เวลาไทย) ตัวเดียวกับที่ใช้เขียน `วันที่ยืนยันคำสั่งซื้อ`, ไม่มีก็ใช้วันสร้าง)
   - `data sec/tools/pancake_sync.mjs`: ส่ง `--chats <tmp>.json` ให้ export แล้วหลังอ่านไฟล์ (ขั้น 1)
     ส่งคู่ทั้งหมดไปที่ RPC `save_order_chats` ของ Supabase เว็บแอดมิน
     ตั้งค่าใน `data sec/private/hylme_admin.json` `{ url, anonKey, code }` (private/ ไม่ขึ้น git)
     ส่งก่อนจุดที่ "ไม่มีออเดอร์เปลี่ยน" return ออก และไม่ส่งตอน `--dry-run`
2. **ฐานข้อมูลเว็บแอดมิน** (migration `0010_order_chats.sql`)
   - ตาราง `order_chats (order_id text primary key, conversation_id text not null, page_id text, day date not null, updated_at timestamptz)`
     อ่านได้แบบ public เหมือน `pancake_orders` เขียนได้ผ่าน RPC เท่านั้น
   - `save_order_chats(p_code text, p_rows jsonb) returns int` ตรวจรหัสอัปโหลดแบบเดียวกับ `save_orders`, upsert ตาม `order_id`
3. **การ์ดตรวจแท็กในหน้าอัปโหลด** เพิ่มส่วน "ออเดอร์" ต่อวัน (วันเดียวกับที่การ์ดแสดง)
   - ออเดอร์ของวันนั้น = `pancake_orders` ที่ `day` = วันนั้น, มี `page_id` (มาจากแชทเพจ), และ `orderLive` (ไม่ยกเลิก/คืน)
   - แชทของออเดอร์ = `order_chats`; แท็กของแชท = แถว `conversations` ล่าสุด (วันมากสุด) ของแชทนั้น ไม่ว่าวันไหน
   - แสดง: ออเดอร์จากแชทเพจ N ใบ · จับคู่แชทได้ M · แชทติดแท็กปิดแล้ว · แชทยังไม่ติดแท็กปิด (รายชื่อ + เปิดใน Pancake)
     · หาแชทไม่เจอ (ไม่มีคู่ / แชทยังไม่อยู่ในไฟล์ข้อความที่อัปโหลด) · ติดแท็กปิดแต่ไม่พบออเดอร์ (รายชื่อ)
   - ออเดอร์ LINE (`order_chats.conversation_id` ขึ้นต้น `ln_` และ `order_chats.day` = วันนั้น) แสดงเป็นบรรทัดแยก
     "ออเดอร์จาก LINE X ใบ — ไม่มีแชทในไฟล์ข้อความ จึงตรวจแท็กไม่ได้" ไม่นับรวมใน N
     (N = 4 เพจ FB/IG ตาม `page_id` ของ `pancake_orders` เหมือนยอดแอดมินตอนนี้)
   - "ติดแท็กปิดแต่ไม่พบออเดอร์" = แชทของวันนั้นที่แท็กปิดโผล่ครั้งแรกในวันนั้น (`conv_tag_seen`) และไม่มีแถว `order_chats`
     ของแชทนั้นซึ่ง `order_chats.day` อยู่ในช่วง วันนั้น −3 ถึง +3 วัน — ใช้วันจาก `order_chats` เอง ไม่ต้องรอไฟล์ออเดอร์
     ของวันถัดไป เพราะคู่เข้าทุกชั่วโมง · ถ้าวัน +3 ยังมาไม่ถึง ให้หมายเหตุว่า "ออเดอร์ที่ยืนยันหลังจากนี้อาจยังไม่เข้า"
   - ยังไม่มีออเดอร์ของวันนั้นในระบบ → แสดงบรรทัด "ยังไม่มีไฟล์ออเดอร์ของวันนี้" แทนตัวเลข
   - ดึงจาก Supabase เฉพาะวันที่การ์ดแสดง (ออเดอร์ ~30 ใบ/วัน + คู่ + แถวแชทของคู่นั้น) — ไม่โหลดทั้งตาราง

## Non-goals / Anti-goals

- ไม่ส่งยอดเงิน สินค้า สถานะ ชื่อ เบอร์ หรือที่อยู่ จากตัวดึง — แค่ 4 ช่องข้างบน
- ยอดออเดอร์และยอดขายในเว็บแอดมินยังมาจากไฟล์ที่อัปโหลด ต้องเหมือนเดิมทุกตัว
- ตัวดึงของ dashboard หลักต้องทำงานเหมือนเดิมทุกอย่าง: ถ้าส่งคู่ไม่สำเร็จ (ไม่มีไฟล์ตั้งค่า, เน็ตล่ม, รหัสผิด)
  แค่เขียน log ⚠ แล้วทำงานต่อ ห้ามทำให้รอบของ dashboard ล้มหรือข้าม
- ไม่ยิง Pancake API เพิ่ม (ใช้รอบเดิมที่ห่างกันอย่างน้อย 55 นาที)
- ไม่ใส่คำตัดสินแอดมิน

## Approaches

- **ง. เลขแชทจาก API ส่งแค่คู่เลข ← เจ้าของเลือก** แม่นที่สุด ไม่มีเบอร์ ยอดเงินไม่เปลี่ยน
- ก. เก็บเบอร์เป็นรหัสลับ — จับคู่ได้เฉพาะแชทที่ลูกค้าพิมพ์เบอร์ (8–21 แชท/วัน) ไม่พอ
- ข. จับคู่ในเบราว์เซอร์ตอนอัปโหลดพร้อมกัน — พลาดเมื่อเบอร์อยู่คนละวัน
- ค. ดึงออเดอร์ทั้งชุดจาก dashboard หลัก — ยอดต้องเป็นแบบหลังแก้ไข งานใหญ่ ยังไม่จำเป็น

## Constraints

- `HYLME_CRM_V3` ไม่ใช่ git repo → สำรองไฟล์ก่อนแก้
- `data sec` เป็น git repo; `private/` ห้ามขึ้น git
- Supabase โปรเจกต์ใช้ร่วมกับ dashboard หลัก — migration แตะแค่ตารางใหม่ ห้าม revoke สิทธิ์ฟังก์ชันอื่น
- โควตา Supabase Free: ตารางใหม่เล็ก (~30 แถว/วัน); การ์ดดึงเฉพาะวันที่แสดง

## Calls ของผม (แก้ได้)

- เพิ่มวันยืนยันเป็นช่องที่ 4 (จาก builder check: ถ้าไม่มี ช่วง ±3 วันต้องรอไฟล์ออเดอร์ของวันถัดไป) — วันที่ไม่ใช่ข้อมูลลูกค้า
- ออเดอร์ LINE แยกบรรทัด ไม่นับใน N (จาก builder check) — แชท LINE ไม่อยู่ในไฟล์ข้อความ ตรวจแท็กไม่ได้อยู่แล้ว
- ส่งคู่ของ 45 วันที่ตัวดึงอ่านอยู่แล้วทุกรอบ (upsert ซ้ำได้ ไม่เพิ่มแถว)
- ช่วง ±3 วันสำหรับ "ติดปิดแต่ไม่พบออเดอร์" — กันกรณีปิดวันนี้ กดยืนยันพรุ่งนี้
- ครั้งแรกเติมย้อนหลังด้วยการรันตัวดึงหนึ่งรอบ (45 วัน)
- เจ้าของต้องสร้างไฟล์ `private/hylme_admin.json` เอง (ใส่รหัสอัปโหลด) — ผมเขียนตัวอย่างให้ ไม่เห็นรหัส
