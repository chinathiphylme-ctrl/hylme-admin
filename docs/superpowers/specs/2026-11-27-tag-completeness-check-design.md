# ตรวจแท็กครบไหม ตอนอัปโหลดไฟล์ข้อความ — Design (ฉบับสั้น)

วันที่ 27 พ.ย. 2026

## Intent

เจ้าของอยากรู้ว่าทำไมลูกค้าไม่ซื้อ จึงให้แอดมินไปหาสาเหตุมาแล้วติดเป็นแท็ก ถ้าแอดมินไม่ติด ข้อมูลก็ไม่ครบ
และสรุปสาเหตุไม่ได้ เจ้าของจึงอยากให้ระบบตรวจเองตอนอัปโหลดไฟล์ข้อความว่าติดแท็กครบไหม
โดยไม่ต้องเข้าไปไล่ดูเอง

ข้อมูลจริง 12–26 พ.ย.: แชทที่ลูกค้าเงียบและยังไม่ปิดมี 814 แชท แต่มีเหตุผลไม่ซื้อแค่ 48 แชท (~6%)
วันที่ 26 พ.ย. มีแชทที่ติดแท็กครบตามนิยามด้านล่าง 13 จาก 110 แชท

## นิยาม "ติดแท็กครบ" (เจ้าของเลือกตามที่เสนอ)

แชทหนึ่งแชทถือว่าครบเมื่อผ่านทุกข้อที่ใช้กับแชทนั้น:

1. มีชื่อแอดมิน (`พี่ก้อย` / `นุ่น🤍`) ใช้กับทุกแชท
2. ถ้ายังไม่ปิด ต้องมีแท็กขั้น 1.–10.
3. ถ้าปิดแล้ว (`ปิด` / `ปิดAds` / `ปิดOrganic`) ต้องมีแท็กเหตุผลที่ซื้อ (`BUY_REASON_TAGS`)
   และต้องใช้ `ปิดAds` / `ปิดOrganic` ไม่ใช่ `ปิด` เฉยๆ
4. ถ้ายังไม่ปิดและมีแท็กเงียบ (`อ่านไม่ตอบ` / `ไม่เปิดอ่าน` / `ทักซ้ำไม่ซื้อ`) ต้องมีเหตุผลที่ไม่ซื้อ (`LOST_REASON_TAGS`)

## Goals

- หลังบันทึกไฟล์ข้อความสำเร็จ หน้าอัปโหลดจะขึ้นการ์ด "ตรวจแท็ก" ทันที ทีละวันที่อยู่ในไฟล์
  (ถ้ามีหลายวัน วันล่าสุดกางไว้ วันอื่นพับไว้):
  - หัวการ์ด: วันที่ · จำนวนแชท · ครบกี่แชท
  - นับตามข้อ 1–4 ข้อ 3 กับข้อ 4 บอกเป็น "X จาก Y" (Y = แชทที่ข้อนั้นใช้)
  - แยกตามแอดมิน: แต่ละชื่อกี่แชทที่ยังไม่ครบ แชทที่มีสองชื่อนับให้ทั้งสองคน
    แชทที่ไม่มีชื่อแยกเป็นแถว "ไม่มีชื่อ"
  - รายชื่อแชทที่ยังไม่ครบ (พับไว้): เพจ · เวลาล่าสุด · ข้อที่ขาด · ปุ่ม "เปิดใน Pancake"
- คำนวณจากแชทที่อ่านจากไฟล์ในเบราว์เซอร์ ไม่ดึงข้อมูลจาก Supabase เพิ่ม (โควตา)

## Non-goals / Anti-goals

- ไม่ใส่คำตัดสิน (ดี / แย่ / ควร…) กับแอดมิน แสดงแค่ตัวเลขและเรียงตามข้อ
- ไม่แสดงชื่อลูกค้า เบอร์โทร หรือข้อความ (เหมือนการ์ดแท็กที่ขาดในหน้าภาพรวม)
- ยังไม่เทียบกับออเดอร์ POS เพราะแท็กปิดเก่าจากการซื้อครั้งก่อนยังค้างอยู่ ทำให้ตัวเลขเพี้ยน
  (12–26 พ.ย. แชทติดปิด 450 แต่ออเดอร์จากเพจ 362) ถ้าจะทำต้องจับคู่รายคนด้วยเบอร์ในเบราว์เซอร์ ซึ่งเป็นงานแยก
- ไม่เพิ่มแท็บหรือเมนูใหม่ ไม่บันทึกผลตรวจลงฐานข้อมูล

## Approaches

- **ก. ขึ้นในหน้าอัปโหลดทันทีหลังบันทึก ← เจ้าของเลือก** ตรงกับที่ขอว่า "ตอนนำเข้าให้ตรวจเอง" ไม่ต้องเพิ่มเมนู
- ข. แยกเป็นแท็บ "ตรวจแท็ก" เลือกวันได้ ย้อนดูง่ายกว่า แต่ต้องกดเข้าไปดูเอง
- ค. ทำทั้งสองแบบ งานมากสุด

## Calls ที่ผมตัดสินเอง (แก้ได้)

- ใช้นิยามแท็กขั้น 1.–10. จาก `numberOf` ที่ยังไม่ commit อยู่ในเครื่อง (ตารางขั้น 1.–10.)
  จะ commit งานนั้นแยกก่อน แล้วค่อยต่อยอด
- ตรรกะตรวจอยู่ใน `src/metrics/tagCheck.ts` (ฟังก์ชันล้วน + เทสต์) การ์ดอยู่ใน `src/ui/TagCheckCard.tsx`
- แชทลูกค้าเก่าที่มีแท็กปิดค้างจากครั้งก่อนจะถูกนับเป็น "ปิดแล้ว" ตามแท็กที่เห็น
  (ไฟล์ไม่บอกว่าแท็กติดเมื่อไหร่) ผมจะเขียนหมายเหตุไว้ใต้การ์ด
